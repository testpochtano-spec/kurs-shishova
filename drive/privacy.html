Privacy Policy

VideoUpload Automation · Effective September 20, 2026

VideoUpload Automation is a private desktop video-processing and publishing workflow. This policy covers its Google Drive integration and the handling of content passed through the configured publishing workflow. The operator can be contacted at testpochtano@gmail.com.

Data we access

  • Google authorization data: access tokens, refresh tokens, granted permissions, and token expiry information needed to connect the application to Drive.
  • Working files: video content, file and folder names, identifiers, sizes, links, and upload metadata for the files the application is permitted to access.
  • Workflow records: locally prepared clips, transcripts, titles, descriptions, cover images, processing errors, and delivery status associated with the selected content.

The desktop uploader requests the limited drive.file permission for files created by, or explicitly made available to, the app. This grant is not permission to read the whole Drive. A separate service account used by the publishing process has access to folders explicitly shared with it. The Drive integration does not request Gmail, Contacts, or Calendar access.

Purpose of processing

Data is used to prepare the operator's content, upload and locate working files, recover interrupted transfers, prevent duplicate uploads, and deliver content according to the operator's configured schedule. Tokens are used only to authenticate API requests and refresh access. The application does not sell Google user data, use it for advertising or profiling, or use it to train general-purpose AI models.

We apply the Google API Services User Data Policy, including its Limited Use requirements, to the use and transfer of Google API data. Access is limited to the authorized workflow and necessary support, security, or legal purposes.

Storage and security

Credentials, configuration, processing artifacts, and delivery logs are stored as local files on the operator's computer. Uploaded working media is stored in the configured Google Drive folder. Google API requests use HTTPS. The operator is responsible for protecting the computer, restricting local access, and securing any backups.

This informational website does not receive OAuth tokens, authorization codes, or video uploads. Google authorization is completed by the desktop application through a local callback. These pages do not include analytics scripts, advertising, or application tracking cookies. GitHub Pages hosts the website and may process connection data, such as IP addresses, under GitHub's privacy statement.

Sharing and service providers

Google processes authentication and Drive storage requests. At the operator's direction, selected media and publishing text can be sent to enabled YouTube, VK, Instagram, Threads, or TikTok integrations. Dropbox may be used as temporary media hosting for configured destinations. Where enabled, relevant media or text may be processed by Google Vertex AI/Gemini to prepare metadata or cover images; Ollama processing runs locally.

Each provider applies its own terms and privacy practices. Public posting can make selected content available to that platform's audience. Authorizing Drive alone does not authorize an unrelated destination: platform connections and the publishing schedule are configured separately. Google authorization credentials are not published with media or on GitHub Pages.

Retention, revocation, and deletion

Local files, queue records, and logs remain until the operator removes them or the configured cleanup process removes them. Drive files and copies sent to other providers remain until removed in the corresponding service, subject to that provider's retention rules. No universal automatic deletion period is promised.

You can revoke the application's Google access from Google Account connections. Revocation stops future authorized access but does not delete existing files or published posts. Stop scheduled jobs before removing local credentials, working files, and backups. Remove Drive files and any published copies separately. Service-account folder access can be withdrawn in Drive sharing settings.

For access, correction, or deletion requests, contact testpochtano@gmail.com. Do not send passwords, tokens, or sensitive source material by email. We may ask for information needed to identify the relevant record and confirm your authority over it.

Changes

Material changes to data use will be reflected on this page before they apply. Additional permissions or materially different uses require appropriate authorization. The effective date above identifies this version.
